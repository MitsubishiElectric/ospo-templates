## Types of Contributions
<!--プロジェクトがどのような種類のコントリビューションを求めているのかを記載します。[推奨]-->
本プロジェクトでは下記のコントリビューションを対象としています。
1. **バグ報告**:  
　バグを見つけた場合は、Issueを作成して報告してください。再現手順や関連するスクリーンショットなど、できるだけ詳細に記載してください。

2. **機能リクエスト**:  
　新しい機能のアイデアがある場合は、Issueを作成して議論してください。機能の詳細とその有用性を説明してください。

3. **コードの貢献**:  
　コードを貢献したい場合は、以下の手順に従ってください。

4. **ドキュメント**:  
　ドキュメントの改善も貴重な貢献です。既存のドキュメントの更新、新しいドキュメントの追加、または誤字の修正などが含まれます。

5. **テスト**:  
　プロジェクトをテストし、見つけた問題を報告することで貢献できます。また、コードベースのテストを書くことも貢献の一つです。

6. **脆弱性通知**:  
　発見した脆弱性については、セキュリティ上の観点からIssueやプルリクエストではなく、メーリングリスト（foo@bar）に送信してください。

## Contribution Workflow
<!--コントリビューションの流れを記載します。[必須]-->
1. **Issueを確認、作成する**:  
　既存のIssueを確認し、同じ問題や提案がないか確認してください。無い場合は、新しいIssueを作成し、できるだけ詳細に記載してください。

2. **リポジトリをフォークする**:  
　リポジトリを自分のGitHubアカウントにフォークし、ローカル環境にクローンします。

3. **ブランチを作成する**:  
　作業用の新しいブランチを作成します。ブランチ名はわかりやすい名前にしてください。
    ```bash
    git checkout -b feature/新機能名
    ```
4. **変更を加える**:  
　新しいブランチで変更を加えます。コードがプロジェクトのコーディング標準に従っていることを確認してください。

5. **変更をコミットする**:  
　意味のあるコミットメッセージを付けて変更をコミットします。
    ```bash
    git commit -s -m "Add 新機能名"
    ```
   -s を付けると、後述の Developer Certificate of Origin (DCO) に必要な Signed-off-by: 行が自動で追加されます。

6. **変更をプッシュする**:  
　変更を自分のフォークしたリポジトリにプッシュします。
    ```bash
    git push origin feature/新機能名
    ```
7. **プルリクエストを作成する**:  
　GitHub上でオリジナルのリポジトリに対してプルリクエストを作成します。変更内容を明確に説明し、関連するIssueをリンクしてください。

## Developer Certificate of Origin (DCO)
<!--DCOを利用する場合に記載します。[推奨]-->
　本プロジェクトは [Developer Certificate of Origin（DCO）](https://developercertificate.org/) を採用しています。DCO は、コントリビューターが「その貢献を提出する権利があること」および「本プロジェクトのライセンス条件のもとで提出すること」を確認するための仕組みです。

[（日本語参考訳）](https://developercertificate.opensource.jp/)

1. **DCO に同意すること**  
　本プロジェクトに対してコミット、Pull Request、パッチ、またはその他の形で貢献する場合、DCOに同意したものとみなします。

2. **Signed-off-by の付与**  
　すべてのコミットには `Signed-off-by:` 行を含めてください。
  ```bash
　　Signed-off-by: 氏名 <メールアドレス>
  ```  
　　　例: Signed-off-by: 山田太郎 <taro@example.com>

3. **付け方**  
　Signed-off-by: 行は、次のコマンドで自動追加できます。
  ```bash
　　git commit -s
  ```
　　　または
  ```bash
　　git commit --signoff
  ```
4. **PR に含まれるコミット**  
　Pull Request に含まれるすべてのコミットに Signed-off-by: 行が必要です。  
　コミットを追加・修正した場合は、再度 sign-off が付いていることを確認してください。

5. **注意事項**  
    - 他者のコードや文章を使用する場合は、適切な権利・許諾を確認してください。  
    - 共同作成物の場合は、必要に応じて共同著作者の同意を得てください。  
    - 企業や団体の業務として作成した場合は、提出権限を確認してください。  
    - Signed-off-by: は、著作権の譲渡を意味するものではありません。

## Issue and Pull Request Guidelines
<!--Issueとプルリクエストのガイドラインを記載します。[推奨]-->
- **Issue**: バグ報告や機能提案は、できるだけ詳細に記載してください。再現手順やスクリーンショットがあると助かります。
- **プルリクエスト**: プルリクエストは、関連するIssue番号をリンクし、変更内容を簡潔に説明してください。
